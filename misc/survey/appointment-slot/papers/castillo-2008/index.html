Efficient Resource Management using Advance Reservations for Heterogeneous Grids

異なる性能の資源が混ざるグリッドでの、事前予約を使った効率のよい資源管理

  • Claris CastilloNorth Carolina State University
  • George N. RouskasNorth Carolina State University
  • Khaled HarfoushNorth Carolina State University

グリッド計算で仕事を事前に予約すると、各サーバーの予定表には予約と予約の間に大きさのばらばらな空き期間が残る。新しい要求のたびに空き期間を端から調べると、サーバーと予約の期間が増えるほど遅くなる。Castillo らは空き期間を平面上の点、要求を直線に変換し、「入る空き期間」を点が直線より下にあるかどうかで判定できるようにした。速度ごとに木構造を持ち、遅いサーバーから順に探すことで、大きなグリッドでも速く割り当てられる。

背景

事前予約を受けると、サーバーの予定表に大きさのばらばらな空き期間が残り、その管理が重くなる

グリッドでは、利用者が「この時刻以降に始めて、締切までに終えたい」仕事を前もって予約できると、計画が立てやすい。一方で予約を受けるほど、各サーバーの時間軸には予約と予約の間の空き期間が増える。新しい要求が来るたびに、どのサーバーのどの空き期間に入るかを探す必要がある。論文の前の段階の研究（IPDPS 2007）は、同じ速度のサーバーだけを考えていた。この論文は速度の違うサーバーが混ざる場合に広げる。

問題設定

要求は開始可能時刻・仕事量・締切の 3 つで表し、締切を守れない要求は断る

スケジューラは \(n\) 台のサーバーを管理する。サーバー \(i\) の処理速度を \(\mu_i\)（単位時間あたりの仕事量）とする。要求 \(j\) は組 \((r_j, l_j, d_j)\) で、\(r_j\) は開始できる最も早い時刻、\(l_j\) は仕事量、\(d_j\) は締切（\(d_j \ge r_j + l_j\)）である。要求はランダムな時刻に次々に届き、締切までに終えられないときは断られる。目的は断られる仕事の割合（仕事の損失率）を小さくし、利用率を大きくすることである。

サーバー \(i\) の空き期間 \(k\) を \((st_k, et_k, c_k)\) で表す。\(c_k = \mu_i\,(et_k - st_k)\) は、その空き期間にこなせる仕事量である。要求がこの空き期間に入る条件は 2 つある。

  • 開始時刻の条件：締切に間に合う時刻までに空きが始まる。\(st_k \le d_j - l_j/\mu_i\)。
  • 容量の条件：開始できる時刻から空きの終わりまでに、仕事量 \(l_j\) をこなせる。論文は空き期間を傾き \(-\mu_i\) の線分（時刻とともに残りの仕事量が減る）として描き、それが要求の線分より上にあることとして表す。

図1　論文の幾何的な見方の模式図（解説者による作図）。要求の線分は速度 1 の基準サーバーで測る。

速度の違いは Godfrey と Karp の考え方にもとづく「多数化の順序（majorization）」で比べる。速度の種類 \(H\)、台数 \(n\) を固定し、総処理能力を同じにしたまま、速度の分布のばらつきが大きい順に段階 \(L\) を付ける。

手法

空き期間を点、要求を直線に変換すると、容量の条件は「点が直線より下にある」という問い合わせになる

論文は双対変換を使う。空き期間を点 \((-\mu_i,\, -\mu_i\, et_k)\) に、要求を直線 \(y = r_j x - l_j\) に写す。同じ速度 \(\mu\) のサーバーの空き期間は、すべて縦の線 \(x=-\mu\) の上に並ぶ。容量の条件は、その縦の線の上で点が直線より下にあることになる。

\[ -\mu\, et_k \ \le\ r_j\,(-\mu) - l_j \quad\Longleftrightarrow\quad \mu\,(et_k - r_j) \ \ge\ l_j \]

右の式は「開始できる時刻 \(r_j\) から空きの終わり \(et_k\) までに、速度 \(\mu\) で仕事量 \(l_j\) をこなせる」ことを表す（変形は解説者による確認。空きが \(r_j\) より前に始まる場合）。

  • データ構造：速度の種類 \(h\) ごとに 2 段の木を持つ。1 段目 \(T_{\mathrm{primal}}\) は開始時刻で並べた平衡二分探索木で、開始時刻の条件を満たす部分木を見つける。2 段目 \(T_{\mathrm{dual}}\) は双対の座標で並べた木で、各節点に部分木の中で容量が最大の空き期間を持たせ、容量の条件を満たす空き期間を探す。
  • FF-HA+（提案）：速度の遅い種類から順に、この木で入る空き期間を探し、最初に見つかったものに割り当てる。計算量は \(O(H \log^2 V)\)。
  • 比較する方式：すべての空き期間を開始時刻の順に 1 本のリストで持つ先着順（FF-HU。速度の違いを考えない）と、速度ごとにリストを分けて遅い順に探す FF-HA（\(O(HV)\)）。

FF-HA+ は部分木の中で容量が最大の空き期間を返すので、空き期間の断片化はかえって増えると著者は述べている。この論文の工夫は断片化を抑えることより、空き期間の検索を速くすることにある。

実験の結果

木構造の方式は線形の探索より大幅に速く、速度の違いを考えて割り当てると、ばらつきの大きいグリッドほど損失率が下がった

シミュレーションはサーバー 120 台、速度の種類 3、速度のばらつきの段階 4 つ（総処理能力は同じ）で行った。仕事の長さは 80% が 4 時間未満、20% が 4〜36 時間で、平均 5.6 時間とした。締切は \((r_j, r_j + q)\) の一様分布で、既定は \(q = 20\) 時間である。1 回の実行で \(10^6\) 件の仕事を流し、30 回の実行で 95% 信頼区間を求めた。

  • FF-HU と FF-HA の比較：速度ごとに分けて遅い順に探す FF-HA が、すべての負荷で FF-HU より損失率と利用率がよかった（Fig. 2）。
  • FF-HU と FF-HA+ の比較：計算時間は FF-HU のほうが大幅に長く、特に負荷が中程度から高いときに差が大きい。FF-HA+ は利用率が高く、待ち時間が短い。損失率は、低い負荷と高い負荷では同じだが、中程度の負荷では FF-HA+ のほうが高かった（Fig. 4、5）。
  • 速度のばらつき：ばらつきの段階 \(L\) を上げると、損失率と利用率はどちらもよくなり、「多くの場合で大きく」改善した（Fig. 6）。著者は統計的な多重化の効果によると説明する。

予約枠の断片化と予約受付の研究の中での位置づけ

予約の間に残る空き期間を、時刻と長さをもつ区間のまま管理し、要求の時間窓に入るものを探す仕組みである

  • 美容室の予約との対応：サーバーはスタイリスト、空き期間は予約と予約の間の空き時間、要求の \((r_j, l_j, d_j)\) は「この時間帯のどこかで、施術時間 \(l_j\) の連続した空きがほしい」客に当たる。処理速度の違いはスタイリストごとの施術の速さの違いとして読める。
  • 違い：空き期間の選び方は先着順で、断片化を抑える指標は持たない。著者自身も、FF-HA+ が断片化を増やすことを認めている。断片化の指標を研究するなら、この論文の検索の仕組みを使い、どの空き期間を選ぶかの基準を別に作る、という組み合わせ方が考えられる。
  • 関連：容量の次元で、将来の要求の分布から断片化を測る Weng ら（2023）、病院の予約表の空きを詰め直す Lian ら（2010）。
