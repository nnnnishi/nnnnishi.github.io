LCM-Promo: An LLM-Based Uplift Model for Promotion Allocation

LLM をアップリフトモデルとして使うプロモーション配分

ブラジルの iFood では、プロモーションが日や配達の時間帯によって変わる。この論文は 4B パラメータの LLM を取引データで微調整し、文脈と割引の選択肢を並べたプロンプトから次の 1 トークンを予測させる。その出力を「どの割引から買うか」の分布として読み、割引を深くするほど下がらない反応曲線を作る。離脱した利用者を呼び戻す施策の A/B テストでは、従来のSegment-EMAに比べて購入が 1% 増え、プロモーション費用が 6% 減った。

背景

iFood のプロモーションは日や配達の時間帯で変わるので、文脈をそのまま入力に書ける LLM が向いている

論文はプロモーションの対象選びをアップリフトモデリングとして扱う。利用者とセッションの特徴を条件に、あるプロモーションを見せたときに見せないときより購入確率がどれだけ上がるかを推定する問題である。

iFood のプロモーションは短期間で入れ替わり、日、配達の時間帯、商品カテゴリ、割引の仕組みによって変わる。プロンプトに入力するモデルなら、利用者の表現、セッションの文脈、割引の選択肢をそのまま文字列にして入れられる。LCM-Promo は Prosus が進める Large Commerce Model（LCM）の一つである。LCM は利用者・店舗・商品のやり取りの履歴で訓練した、EC 向けの基盤モデルを指す。

手法

次の 1 トークンの確率を購入のしきい値の分布として読み、足し上げて単調な反応曲線を作る

プロンプトには、システムプロンプト、セッションの文脈、LCM が過去のログから作った利用者の行動の要約、アルファベットの識別子を振った割引の選択肢を入れる。ベースモデルは 4B パラメータの密なモデルである。割引 \(d_0,\dots,d_K\) を浅い順に並べて識別子 \(a_k\) を振り、購入しない場合を \(a_\emptyset\) とする。学習では、実際に購入したときの割引の識別子（購入しなかった利用者は \(a_\emptyset\)）を正解ラベルとして、交差エントロピーで微調整する。

推論時は次のトークンの分布をこれらの識別子だけに制限し、合計が 1 になるよう正規化し直す。

\[ q_i(x) = \frac{p_\theta(a_i \mid x)}{\sum_{j=0}^{K} p_\theta(a_j \mid x) + p_\theta(a_\emptyset \mid x)}, \qquad i \in \{0,\dots,K,\emptyset\} \]

この \(q\) を、潜在的な購入のしきい値 \(T\) の確率分布として読む。\(T = d_k\) は「\(d_k\) が、その利用者が買う最も浅い割引である」ことを、\(T = \infty\) はどの割引でも買わないことを表す。離脱者の呼び戻しでは 1 か月に何度か提示を受けても購入はたいてい 1 回なので、実際に購入したときの割引をしきい値の代わりに使う。割引 \(d_k\) を出したときの購入確率は、分布を足し上げた反応曲線になる。

\[ r_k(x) = P(T \le d_k \mid x) = \sum_{j=0}^{k} q_j(x) \]

反応曲線は作り方からして、割引が深くなっても下がらない。「購入なし」にも確率が残るので \(r_K(x) < 1\) になりうる。論文は、割引なしに対するアップリフトがこの曲線からそのまま求まると述べる。

比較として、しきい値の順序をラベルに入れるwaterfall 拡張も試している。割引 \(d_k\) で買った利用者は \(d_k\) 以上のすべての割引を正、買わなかった利用者は \(a_\emptyset\) だけを正とし、これを平滑化したソフトターゲットで交差エントロピーを最小化する。

オンラインの評価

離脱者の呼び戻しの A/B テストで、Segment-EMA に比べて購入が 1% 増え、プロモーション費用が 6% 減った

比較相手の Segment-EMA は iFood がそれまで本番で使っていた方式で、セグメントとプロモーションの組ごとに注文数を指数加重移動平均で予測する。新しい割引、セグメント、文脈を加えるたびにその組で探索が要るので、セグメントを細かく分けられない。

ブラジル全土の離脱者を対象に、1 か月の A/B テストを行った。利用者を無作為に 90% の対照群（Segment-EMA）と 10% の処置群（LCM-Promo）に分け、両群で同じ全体の予算制約と同じ線形最適化の配分器を使った。違うのは反応モデルだけである。結果は購入が相対で 1% 増え、プロモーション費用の総額が 6% 減った。この結果を受けて、LCM-Promo は離脱者全員に展開された。

推論は昼と夜に向けて 1 日 2 回行う。利用者を都市・セッション・ライフサイクルでクラスタに分け、ブートストラップで決めた数の利用者を無作為に抜き出して、クラスタごとの平均の反応曲線を推定する。論文は、この抽出が本番運用を可能にしたと述べる。プロンプトは事前に計算した利用者の表現を使い、自前でホストした vLLM 上の 4B モデルに、著者らが公開している自前 GPU 向けのバッチ推論基盤 BESH を通して送る。計算は H200 8 枚で 1 日 1 時間である。

時間帯などの文脈は Segment-EMA では予測の組を分ける必要があったが、LCM-Promo ではプロンプトに書くだけで済む。そのため配分の単位は約 50 のセグメントから 1,000 を超えるクラスタに、ウォレット構成（論文の語は wallet configuration）は 10 通りから 100 万を超えるプロモーションの組合せに広がった。

オフラインの評価

固定したプロモーションの RCT では、AUUC と Qini は Uplift Random Forest と同程度で、Uplift@30 では下回った

展開の前に、プロモーションを 1 つに固定した RCT のデータで評価した。比較相手は causalml で実装した Uplift Random Forest で、過去数か月の RCT データで学習した強いベースラインである。LCM-Promo は過去の本番ログで学習し、RCT は評価にだけ使う。

本番では複数の割引の深さ、セッションの文脈、ウォレット構成を扱うので、このベンチマークはそれより範囲が狭い。論文はこの結果を、オフラインで優れていることの証拠ではなく、オンラインのテストに進むための確認として扱っている。waterfall 拡張で学習した LCM-Promo は大きく下回った。論文は、複数のラベルを正とするソフトターゲットが、次のトークンを予測する LLM の事前学習の目的と食い違うためだろうと推測している。

予算制約つきアップリフトの中での位置づけ

予算の配分は既存の線形最適化に任せ、その入力となる割引ごとの反応曲線を LLM で推定する

この論文が推定するのは、割引の深さごとの購入確率 \(r_k(x)\) で、割引なしに対するアップリフトはここから求める。処置は複数の割引の深さとその組合せで、費用はプロモーションの費用の総額として評価している。

予算制約は配分の段階で扱う。A/B テストの両群は同じ全体の予算制約のもとで同じ線形最適化の配分器を使う。論文はこの配分器について、オンライン多肢選択ナップザックで配分する Albert と Goldenberg（CIKM 2022）を引用している。配分器の定式化はこの論文には書かれておらず、論文の貢献は反応モデルの側にある。反応曲線が割引について単調になることが、予算つきの配分とオフラインのアップリフト評価の両方に使えると論文は述べる。

結果は一つのライフサイクルの段階（離脱者の呼び戻し）と一つのプラットフォーム（iFood）に限られる。ほかの段階やプラットフォームへの拡張は進行中だと論文は述べている。
