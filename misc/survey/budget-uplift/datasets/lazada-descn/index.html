東南アジアの EC サイト Lazada のバウチャー（クーポン）配布の記録から作ったデータで、DESCN（KDD 2022）の著者が GitHub で公開している。学習用（926,669 行）は運用の施策で配布先を選んだ偏った割付、テスト用（181,669 行）は施策の影響を受けない利用者に無作為に配ったランダム化比較試験（RCT）の記録である。結果は 0/1 の label が 1 列あるだけで、金額やコストの列はない。

由来

Lazada のバウチャー配布の本番データから、偏った割付の学習用と RCT のテスト用を分けて公開した

DESCN の論文によると、元のデータは Alibaba グループの東南アジアの EC サイト Lazada で、実際にバウチャーを配った業務の記録である。本番の環境では運用の狙い（targeting strategy）に沿って配布先を選んでいるので、処置の割付は偏る。著者らはこの記録を学習用とした。一方で、狙いの対象から外れていて、配布を RCT で決めた少し小さい利用者の集団があり、その記録をテスト用とした。論文は、学習用とテスト用で偏った処置と無作為な処置を同時に持つ産業データは、知る限りこれが初めてだとしている。

論文の要旨によると、公開したのは本番データの「標本（a sample）」である。DESCN という手法は掲載論文（ECUP、MTMT など）でも比較相手として使われているが、このデータの由来を説明している資料は DESCN の論文と GitHub の README だけである。データを集めた期間、国、バウチャーの額面は、どちらにも書かれていない。

リポジトリ全体のライセンスは GitHub 上では BSD 2-Clause と表示される。ただし、リポジトリの LICENSE と、データの zip に入っている LICENSE は同じファイルで、本文は Nginx のソースコードのライセンス（Igor Sysoev、Nginx, Inc.、Alibaba Group などの著作権表示つき）である。データの利用条件を個別に定めた記述は見つからなかった。

各行は 1 人分の記録で、ID、結果（label）、処置（is_treat）と、名前のない特徴量 83 個からなる

ファイルは学習用の full_trainset.csv とテスト用の full_testset.csv の 2 つで、どちらも 86 列のカンマ区切りである。全件を読んで確かめたところ、空のセルはなく、label と is_treat には 0 と 1 以外の値がなかった。data_id は「train_0」「test_0」のように、ファイルの種類と行番号をつないだだけの通し番号である。

処置と割付

学習用は特徴量から処置をほぼ当てられるほど偏っているが、テスト用の割付は特徴量と関係しない

処置群の割合は学習用で 22.2%（処置群 205,480 人、対照群 721,189 人）、テスト用で 52.1%（処置群 94,682 人、対照群 86,987 人）である。学習用は論文のいう sample imbalance（群の大きさの偏り）も持つ。

割付が特徴量とどれだけ結びついているかを、2 つの方法で確かめた。1 つ目は処置群と対照群の平均の差を標準偏差で割った標準化差である。学習用では 83 個中 67 個で絶対値が 0.1 を超え（中央値 0.41、最大は f9 の 0.91）、テスト用では 1 つもなかった（最大 0.052）。2 つ目は特徴量から処置群かどうかを当てるロジスティック回帰（傾向スコアのモデル）である。全件で当てはめた AUC は学習用で 0.905、テスト用で 0.526 だった。学習用では、推定した傾向スコアが 0.05 未満の行が全体の 38.6% あり、処置群と対照群の分布はほとんど重ならない（図2）。

たとえば f0（0〜5 の整数）の値ごとに処置群の割合を見ると、学習用では 9.3%（f0 = 0）から 31.8%（f0 = 2）まで違うが、テスト用ではどの値でも 51〜53% である。

論文の値との違い

公開されたのは論文の実験データのおよそ 2 割の標本で、処置率と正例率は論文の値とほぼ同じである

DESCN の論文の Table 1 は本番データを学習用 4.17M 行（処置群 0.92M、対照群 3.25M）、テスト用 0.91M 行（処置群 0.47M、対照群 0.43M）としている。公開されたファイルの行数は学習用でその 22.2%、テスト用で 20.0% にあたる。処置群の割合（学習用 22.2% と論文 22.1%、テスト用 52.1% と 51.6%）と正例率（1.99% と 2.0%、3.52% と 3.5%）は、論文の値とほぼ同じである（表3）。全件から計算した群ごとの人数と正例の数は、README の表の値とすべて一致した。ベンチマーク論文の Table 2 の値も、公開されたファイルの値と一致する。

文献リストの表の「学習 約417万行・テスト 約91万行」は論文の Table 1 の値で、公開されたファイルの行数ではない。

なお、リポジトリのノートブック（DeepModels_real_data.ipynb）は、公開ファイルと同じ名前の 2 ファイルを読み、学習用から 90% を無作為に 5 回取り出して実験している。2022 年 2 月 15 日の実行として残っている AUUC の平均と標準誤差（DESCN で 0.033976 ± 0.000645、TARNet で 0.030861 ± 0.002132 など）は、丸めると論文の Table 2 の値と一致する。

基本統計

学習用で素朴に比べた差は +4.72 pt だが、RCT のテスト用では +0.37 pt で、12.6 倍の開きがある

学習用では、処置群の正例率が 5.66%、対照群が 0.94% で、差は +4.72 pt、比は 6.0 倍になる。テスト用では処置群 3.70%、対照群 3.33% で、差は +0.374 pt（標準誤差 0.086 pt、95% 信頼区間 0.205〜0.543 pt）、対照群に対する相対的な上昇は +11.2% である（図3、表4）。テスト用は無作為に割り付けているので、この差がテスト用の集団での平均処置効果の推定値になる。学習用の差は、配られやすい人がもともと反応しやすいことによる偏りを含む。

学習用でも、推定した傾向スコアで重みをつけて比べる（逆確率重みづけ、IPW）と、差は +0.53 pt まで縮む。ただし、これは線形のロジスティック回帰で傾向スコアを推定した解説者の試算で、学習用とテスト用は対象者の集団も違う（テスト用の対照群の正例率 3.33% は、学習用の対照群の 0.94% より高い）。学習用の効果の正解は分からない。

正例はテスト用の対照群で 2,893 件、処置群で 3,503 件しかない。差の標準誤差は差の 23% にあたり、テスト用で手法どうしの AUUC を比べるときの誤差も小さくはない。

予算制約つきの実験での使われ方

文献リストで使うのはベンチマーク論文 1 本で、コストは置かず、RCT のテスト用で順位づけを比べている

文献リストでこのデータを実験に使っている論文は次の 1 本である。予算制約や処置のコストを使った実験はない。DESCN という手法は ECUP、MTMT、FunnelCausalNet などで比較手法として使われているが、それらの論文は別のデータで評価している。

  • 深層アップリフトのベンチマーク（arXiv 2024）　DESCN の論文の分け方にならうとして、学習用を 9:1 で学習と検証に分け、RCT のテスト用をそのままテストに使う。乱数シードは 0〜9 とした。重複除去と特徴量の正規化の有無を組み合わせた 4 通りの前処理で 13 手法を比べ、テスト QINI の 1 位は SNet、DESCN、SNet、CFRNet と条件ごとに入れ替わった。解説ページによると、EFIN は検証 QINI では 4 条件すべてで 1 位だったが、テストでは 13 手法中 12〜13 位で、検証とテストの順位相関は −0.52〜0.09 だった（解説者が論文の表から計算）。偏りのある学習用から切り出した検証データでの順位は、RCT のテストでの順位とほとんど一致しなかったことになる。

データの出典の DESCN の論文自体は、偏った学習用で学習し（公開コードでは学習用から 90% を無作為に取り出す）、テスト用での AUUC（scikit-uplift の qini_auc_score）と、処置群の平均処置効果の誤差 \(\epsilon_{ATT}\) で 8 手法を比べている。予算制約つきの研究でこのデータを使うには、配布の費用を別に仮定する必要がある。全員の費用が同じだと仮定すれば、予測した効果の順に配るときの曲線（Qini 曲線など）は、配布人数（予算）を変えたときの成果として読める（解説者の注）。

注意点

金額とコストの列がなく、label の意味も明記されていない

  • 金額とコストがない　結果は 0/1 の label だけで、注文の金額もバウチャーの額面も配布の費用もない。処置も配る・配らないの二値である。
  • label の意味　README と論文は label が何を表すかを書いていない。文献リストの表は「購買」としているが、資料からは確かめられなかった。中国語の README は、DESCN が解く問題の例として「クーポンを配るかどうかで購入率がどれだけ増えるか」を挙げているが、このデータの label の定義としてではない。
  • 学習用の行の並び　学習用のファイルは処置について並びが偏っていて、前半の処置群の割合は 15.5%、後半は 28.9% である（テスト用は前後とも 52.1%）。先頭から切り出したり、並べ替えずに分割したりすると、偏った部分集合になる。
  • 重複行　data_id を除くすべての列が前のどれかの行と同じ行が、学習用に 17,976 行（1.9%）、テスト用に 1,792 行（1.0%）ある。特徴量だけが同じ行は 22,715 行と 2,437 行で、最も多いものは学習用で 399 行が同じ特徴量を持つ。テスト用の 4,388 行は、学習用のどれかの行と特徴量が同じである（いずれも解説者の計算）。ベンチマーク論文は、重複を除くかどうかで Lazada の手法の順位が変わることを報告している。
  • 重複した列　定数の列（f70）、ほかの列とまったく同じ列、二値の列の 0 と 1 を入れ替えた列がある（表2）。正規化や距離の計算では、同じ情報を何度も数えることになる。
  • テストの正例が少ない　テスト用の正例は 6,396 件で、平均処置効果の差の標準誤差は差そのものの 23% にあたる。小さな AUUC の差は誤差に埋もれやすい。
  • 評価コードの選び方　DESCN のリポジトリの評価スクリプト（eval4real_data.py）は、各反復で、エポックごとに保存したテスト用の予測（設定では 5 エポック分）のうち、テスト用での AUUC が最大のものを採っている。テスト用でモデルを選んでいることになる。論文の Table 2 の値を、検証データでモデルを選ぶ手順の結果と比べるときは、この違いに注意する。
  • 公開版は標本　論文の Table 1 の行数は公開版の約 5 倍である。論文や文献リストの行数を引くときは、どちらの値かを確かめる。
取得方法

README の Dropbox のリンクから取得でき、ファイルの MD5 は README の値と一致した

README は Google Drive、Baidu Drive（抽出コード 75hr）、Dropbox の 3 か所を案内している。解説者は 2026 年 11 月 23 日に、Dropbox のリンクの末尾を dl=1 にしてログインせずに lzd_data_public.zip（101,629,017 バイト）を取得した。zip と中の 2 ファイルの MD5 は README に載っている値と一致した。zip を展開すると 574 MB（学習用 476,424,638 バイト、テスト用 97,760,488 バイト）になる。このページの統計はこのファイルから計算した。
