Criteo が複数の広告主で行った広告のランダム化比較試験（RCT）を一つにまとめた公開データで、13,979,592 行ある。各ユーザーを広告の対象にするかどうか（treatment）を無作為に決め、その後 2 週間の訪問（visit）と購入（conversion）を 0/1 で記録している。予算制約つきアップリフトの論文では訪問をコスト、購入を売上とみなして評価に使うことが多い。

由来

複数の広告主で行った広告の RCT を、処置率をそろえて一つにまとめたデータである

Criteo は母集団の一部に広告を出さない incrementality test（広告の効果を測るための RCT）を複数の広告主で実施した。広告主ごとに、ある時点で各ユーザー（ブラウザの cookie で識別）を処置群か対照群に無作為に割り当て、それまでの行動から特徴量を作る。処置群には割り当て後もふだんどおり個人に合わせた広告を出し、対照群には出さない。割り当て後の 2 週間に、広告が表示されたか、広告主のサイトを訪れたか、購入したかを記録した（図1）。

広告主ごとに処置率が違ったため、そのまま合わせると、どの試験の行かが処置と結果の両方に関わる隠れた交絡になる。そこで全ての試験を同じ処置率で抜き出してから合わせた。プライバシー保護のため、広告主も特徴量の名前も公開していない。特徴量の値はランダムなベクトル空間に射影し、ラベルには不均一な負例サンプリングをかけて、元の効果の大きさを推測できないようにしている。データ論文の内容は論文の解説ページにまとめてある。

ライセンスは配布ページと Hugging Face のリポジトリでは CC BY-NC-SA 4.0（表示・非営利・継承）である。データ論文（arXiv 2111.10106）のデータシートには CC BY-SA 4.0 と書かれているが、このページでは配布元の表記に従う。

列

各行は 1 人のユーザーで、匿名化した特徴量 12 個と、割り当て・表示・訪問・購入の 4 つの 0/1 の列からなる

処置と表示

無作為に決めたのは treatment だけで、広告が実際に表示されたのは処置群の 3.6% にとどまる

treatment は広告の対象にするかどうかの割り当てで、exposure は実際に広告が表示されたかどうかである。scikit-uplift の説明では、treatment は広告主がそのユーザーの RTB オークションに参加するかどうか、exposure はそのオークションに勝ったかどうかにあたる。処置群でも、オークションに勝たなければ広告は表示されない。

全件で確かめると、対照群で exposure が 1 の行は 0 件だった。表示は処置群にしか起きない、いわゆる片側の不遵守（one-sided noncompliance）である。処置群 11,882,655 人のうち表示されたのは 428,212 人（3.60%）で、全体の 3.06% にあたる（図2）。visit が 0 で conversion が 1 の行も 0 件で、訪問せずに購入した記録はない。

このため、効果は treatment で群を分けて比べる。これは「広告の対象にする」という方針の効果（ITT）で、広告を見た人だけの効果ではない。表示の有無で比べると無作為化が崩れる。処置群の中で比べると、表示された人の訪問率は 41.5%、表示されなかった人は 3.49% だが、この差には、どんな人に広告が表示されるかという選ばれ方の違いが混ざっている。論文も、広告システムはユーザーの反応に応じて入札を変えるので、試験中の表示はそれまでのやりとりの影響を受けると述べている。

treatment が exposure を通じてだけ結果に影響すると仮定すれば、ITT を処置群の表示率で割った値が、割り当てられれば表示される人での効果になる。論文はこの種の仮定に触れているが、詳しくは扱っていない。全件で計算すると、訪問で 28.7 pt、購入で 3.20 pt である（解説者の計算）。なお scikit-uplift の fetch_criteo では treatment_col='exposure' も指定でき、ドキュメントの使用例もこの指定になっているが、exposure を処置として扱うと無作為化された比較にはならない。

版の違い

2018 年の v1 は広告主ごとの処置率の違いから効果を水増しできたため、処置率をそろえて抜き直した v2 に置き換えられた

2018 年に AdKDD のワークショップ論文とともに公開された最初の版（v1）は 25,309,483 行で、処置率 0.846、訪問率 0.04132、購入率 0.00229 だった（配布ページと AdKDD 2018 論文の Table 3）。配布ページの正誤表によると、広告主ごとに効果の大きさがそろっておらず、特徴量の分布も広告主ごとに違ったため、特徴量から広告主を見分けるだけでアップリフトの予測が見かけ上よくなるという漏れがあった。

拡張版の論文（arXiv 2111.10106）は、広告主ごとに処置率が違ったため、どの試験のデータかが処置と結果の隠れた交絡になっていたと説明する。v2 では全ての試験を同じ処置率で抜き出し直し、13,979,592 行になった。論文によると v2 は v1 の約 1 年後に公開され、v1 は配布を終えて、初期の利用者には欠陥が知らされた。論文は特徴量から処置を当てられないことを分類器による 2 標本検定で確かめている（p 値 0.137）。

現在のファイル名は criteo-research-uplift-v2.1.csv.gz である。論文のコードのリポジトリはこのファイルを CRITEO-UPLIFTv2 として案内しており、全件から計算した行数、処置率、訪問率、購入率は配布ページに載っている v2 の値と一致した（表3）。v2 と v2.1 の違いを説明した記述は、配布ページ、論文 2 本、Hugging Face のリポジトリ、論文のコードのリポジトリのどれにも見つからなかった。

掲載論文の中には v1 の行数を挙げているものもある。RATE（JASA 2025）の解説ページには、25,309,483 件のデータから標本を取り出したとある。論文どうしの数値を比べるときは、どの版を使ったかを確かめる必要がある。

基本統計

広告の対象にすると、訪問率は 3.82% から 4.85% に、購入率は 0.194% から 0.309% に上がる

処置群と対照群の率の差（ITT の平均処置効果）は、訪問で +1.034 pt（標準誤差 0.015 pt、95% 信頼区間 1.006〜1.063 pt）、購入で +0.115 pt（標準誤差 0.003 pt、0.109〜0.122 pt）である。対照群に対する相対的な上昇は、訪問で +27.1%、購入で +59.4% になる（図3、表4）。

訪問したうちで購入した人の割合は、処置群 6.36%、対照群 5.07%、全体で 6.21% である。購入は全体で 40,774 件、そのうち対照群は 4,063 件しかなく、差の標準誤差は、購入では差の 3.0%、訪問では差の 1.4% にあたる。論文も、購入はラベルの偏りが大きく信号が弱いとして、アップリフトのモデルは主に訪問で作ることを勧めている。

これらの率は不均一な負例サンプリングをかけたあとの値なので、実際の広告の訪問率や効果の大きさを表してはいない。

予算制約つきの実験での使われ方

予算制約つきの論文では visit をコスト、conversion を売上とみなし、費用対効果の順に配ったときの曲線で手法を比べることが多い

このデータには配信の費用も売上額もない。そこで DRP 以降の論文は二値の処置（広告の対象にするかどうか）のもとで、訪問の増加をかかった費用、購入の増加を得られた売上の代わりとみなす。予測した費用対効果の順に配ったときの増分コストと増分売上の曲線の下の面積にもとづく指標（AUCC）で比べるのが典型である。データ全体では、購入の差は訪問の差の 0.111 倍である（解説者の計算）。以下は、文献リストの解説ページに書かれている使い方である。

  • DRP（AAAI 2023）　1,390 万件・特徴量 12 個のデータで、ROI を比べるために訪問をコスト、コンバージョンを売上とみなした。AUCC で、DRP は TPM-SL と Direct Rank を上回った。
  • DFCL（KDD 2024）　先行研究の DPM にならい、visit をコスト、conversion を価値とみなす。DFCL-IFD の AUCC は 0.7859 で、二段階法 TSM-SL の 0.7561 を 3.94% 上回った。
  • E2E マーケティング最適化（arXiv 2023）　DRP の論文にならって訪問をコスト、コンバージョンを価値とし、7:3 に分けて AUCC で比べた。提案法は 0.7904、DRP は 0.7739、二段階法は 0.7561 で、比較手法の値は DRP の論文から引用している。
  • rDRP（ICDE 2024）　DRP の論文と同じデータとハイパーパラメータで、訪問をコスト、コンバージョンを便益とする。学習データが少なく共変量シフトもある設定で、AUCC が DRP の 0.5411 から 0.6087 に上がった。
  • Bi-DFCL（NeurIPS 2025）　RCT データの一部を、模擬した施策方針で観察データに作り替えて使う。visit をコストとみなし、AUCC で評価する。
  • BCCB（arXiv 2026）　v2.1 の 10%（1,397,959 件）を抜き出し、結果は購入とする。配信費用はデータにないので、結果とは独立に対数正規分布から作り（0.05〜5 ドルに切り詰め、平均 0.77 ドル）、リプレイ法で評価した。
  • 購入者のみの学習（CIKM 2025）　処置群と対照群を同数に再標本化し、購入しなかった行の報酬と費用を 0 にして使う。
  • ランキングのメタ学習器（arXiv 2024）　50 万件を抜き出し、「コンバージョン − 訪問」を純収益として使う。
  • 費用を考慮した因果分類（EJOR 2023）　11,647 件を抜き出して使う。解説ページによると、論文の表と本文で Criteo の陽性率などの数値が食い違っている。

注意点

売上額も配信費用もなく、特徴量の意味も分からないので、コストと売上は 0/1 の結果で代用するしかない

  • 金額がない　結果は訪問と購入の 0/1 だけで、購入額も広告の費用もない。訪問をコスト、購入を売上とみなすのは評価のための約束事で、実際の費用（表示や入札の単価）とは関係しない。BCCB のように費用を人工的に作る論文もある。
  • 購入がまれ　購入は全体の 0.29%（40,774 件）で、対照群では 4,063 件である。10% を抜き出すと、対照群の購入は 400 件ほどになる（解説者の概算）。
  • 率は実際の値ではない　不均一な負例サンプリングをかけているので、率や効果の大きさは実際の広告のものではない。費用対効果の絶対値を実務の目安にはできない。
  • 匿名化　特徴量の名前と意味は公開されておらず、値はランダムに射影されている。意味にもとづく解釈や制約は置けない。カテゴリ変数も小数で入っているので、数値として扱うかカテゴリとして扱うかは利用者が決める。
  • 処置の偏り　処置群が 85%、対照群が 15% である。無作為に分割すると、テストデータにも同じ偏りが残る。
  • 重複行　すべての列が前のどれかの行と同じ行が 1,259,545 行（9.0%）、特徴量 12 個だけが同じ行が 1,626,259 行（11.6%）ある（解説者の計算）。深層アップリフトのベンチマークは、重複を除くかどうかで結果が変わることを報告している。
  • exposure は無作為ではない　処置として使うと無作為化された比較にならない（「処置と表示」の節）。
  • 資料の食い違い　配布ページの説明文は特徴量を 11 個とするが、同じページの列の一覧とファイルでは 12 個ある。ライセンスの表記は配布ページとデータシートで違う。2021 年の論文の相対的な上昇は v1 の値と同じである（表3）。
取得方法

配布ページのリンクと scikit-uplift の取得先は使えなかったが、Criteo の Hugging Face リポジトリから同じ名前のファイルを取得できた

配布ページのリンク（http://go.criteo.net/criteo-research-uplift-v2.1.csv.gz）からは、2026 年 11 月 23 日に解説者が試した時点でファイルを取得できなかった（404 を返すか、名前解決できないホストへ転送された）。Criteo のアカウントが Hugging Face に置いたリポジトリ criteo/criteo-uplift には同じ名前のファイル（311,422,618 バイト）があり、このページの統計はこのファイルから計算した。ファイルの SHA-256 は Hugging Face に記録されている値と一致した。

# scikit-uplift 0.5.1（取得先は 2026 年 11 月 23 日時点で 404）
from sklift.datasets import fetch_criteo
X, y, t = fetch_criteo(target_col='all', treatment_col='treatment', return_X_y_t=True)

scikit-uplift の fetch_criteo は、target_col に visit・conversion・all、treatment_col に treatment・exposure・all を指定でき、percent10=True で 10% の版を読む。ただし最新版 0.5.1（2022 年 8 月）のコードにある取得先（Amazon S3 上の criteo.csv.gz と criteo10.csv.gz）も、同じ日に 404 を返した。Hugging Face から取得したファイルを pandas などで直接読めば、同じ列が得られる。

配布ページはデータを使うときに AdKDD 2018 の論文を引用するよう求めている。v2 の作り方に触れるときは、拡張版の arXiv 2111.10106 もあわせて引く。
